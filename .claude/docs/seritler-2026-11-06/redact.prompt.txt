Today `_record_detect_placeholders` (src/cdpilot.py, "Record & Replay (issue #5)" section) has three rules only: secret-shaped selector for input commands, secret URL params / userinfo password, bearer / token-prefix values. The session log (`_slog_redact_args`, the `_SLOG_*` regexes and helpers right above it) is wider. A T1 security review (08.11) traced these leaks into a saved flow: `fill "#login-pw" hunter2` (pw not in `_SLOG_SECRET_NAME_RE`), `fill "input[name=cardnumber]" 4242424242424242`, `intercept headers "*api*" X-Api-Key:abc123`, `eval "localStorage.setItem('api_key','s3cr3t')"`, `tools call login '{"password":"x","user":"u"}'`, `assert-value #pw hunter2`, `--password=x` / `--api-key x` flags.

DESIGN (decided; implement exactly this, change nothing else):
1. ONE SOURCE OF RULES. Extract from `_slog_redact_args` a pure helper `_slog_secret_hits(cmd, args)` that returns the positions the session log would redact as a list of `(index, kind, key)` with kind in {"flag_value", "word_value", "kv_value", "tokenish", "input_value"} and key = the flag / word / kv key name (or None); `_slog_redact_args` must keep its exact behaviour and output (the existing session-log tests stay green) — it may call the helper or stay as is, but the regex set must not be duplicated: the recorder calls the helper. If extraction is not practical, the recorder may call the individual `_SLOG_*` regexes and `_slog_tokenish` directly; copying a regex is forbidden.
2. RECORDER RULES (in `_record_detect_placeholders`, keeping the current three):
   a. every command: each hit from the helper becomes a placeholder. kv / flag / word hits use a slug from the key (`X-Api-Key` -> `x_api_key`, `--password=` -> `password`), otherwise `vN`; only the value part is replaced (`X-Api-Key:{{x_api_key}}`, `--password={{password}}`, `password {{password}}`); vars hint `"<cmd> <key>"`.
   b. input commands: add `assert-value` to `RECORD_INPUT_CMDS`; for fill / type / smart-fill / select / assert-value also placeholder the value when `_slog_tokenish(value)` is true even if the selector is innocent; test the selector with a recorder-only regex `_RECORD_SECRET_SEL_RE` = `_SLOG_SECRET_NAME_RE`'s alternatives plus `\bpw\b|pin|cvv|cvc|card|iban|ssn|tc(?:kn|kimlik)` (input commands only, so `#card-title` in a click is untouched).
   c. `eval`, `eval-batch`, `frame eval`, `multi-eval` (whichever exist): find secret string literals with the session log's `_SLOG_JS_SECRET_CTX_RE` (and `_slog_tokenish` on literals) and replace the literal's content with `{{vN}}` inside its quotes, so replay substitutes it back.
   d. `tools call <name> <json>`: parse the JSON; values whose key matches `_SLOG_SECRET_NAME_RE` become `{{<key slug>}}` (nested objects too); re-serialize compact; `--arg k=v` pairs follow rule a.
   e. unchanged: emails, search terms and other innocent values stay verbatim; `#email` stays verbatim; the e2e/other existing expectations (`fill #password` -> `{{password}}`, hint `fill #password`) must not change.
3. `record stop --save` writes the file with mode 0600 (`os.open(path, O_WRONLY|O_CREAT|O_TRUNC, 0o600)`), still after building the flow and before removing active.json.
