# Day 008 — T1 Foundations

## Topic
Runtime.evaluate vs Runtime.callFunctionOn

## Tweet 1/5 — Hook
`Runtime.evaluate` takes a string, evaluates it in the global context, and returns the result. It works. It's also the shotgun approach. Are you still just throwing JS strings at the console and hoping?

## Tweet 2/5
`Runtime.callFunctionOn` is the scalpel. You pass an `objectId` (a remote handle to a DOM node or object) and execute a function with that object as `this`. No string serialization, proper object scope, and significantly faster for repeated operations.

## Code snippet (tweet 3/5)
```python
# cdpilot eval-batch: N expressions, 1 CDP roundtrip
results = await cdp.eval_batch([
    "document.title",
    "window.location.href",
    "document.querySelectorAll('a').length"
])
# Returns [title, url, link_count] in one WebSocket frame
```

## Tweet 4/5
Roundtrip latency is the silent killer. At 5ms per roundtrip, doing 5 sequential `evaluate` calls costs 25ms minimum on a local socket. `eval-batch` collapses N expressions into 1 frame. At scale, this is the difference between 100 and 1000 pages/minute.

## Tweet 5/5 — Anchor
Why do we keep building tools that treat WebSocket roundtrips like they're free?
