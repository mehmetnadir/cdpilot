# Day 015 — T1 Foundations

## Topic
Target.attachToTarget internals

## Tweet 1/5 — Hook
`Target.attachToTarget` is how you get a `sessionId` to talk to a specific tab. Without it, your CDP commands go to the browser process and mostly fail silently. You'd be surprised how many people skip this step. Ready to go deeper into the session model?

## Tweet 2/5
Key distinction: **Target** is the resource (a tab, a worker, an iframe). **Session** is the connection to that target. You can have multiple sessions to one target, and you can route commands to different sessions over the same WebSocket. This is what makes context pools work.

## Code snippet (tweet 3/5)
```python
# Attach to a target and get a session
resp = await cdp_send("Target.attachToTarget", {
    "targetId": target_id,
    "flatten": True  # flat session model — no nested routing
})
session_id = resp["sessionId"]

# Now route commands to this specific tab
await cdp_send("Page.navigate", {"url": "https://..."}, session_id=session_id)
```

## Tweet 4/5
In cdpilot, session management is handled automatically. You declare N contexts, we allocate targets, track session IDs, and clean up on exit. No ID collisions, no leaked sessions. The `CDPILOT_TARGET` env var pins you to a specific context if you're orchestrating from outside.

## Tweet 5/5 — Anchor
Most tools abstract the session model away. We think understanding it makes you a better engineer — and makes your debugging a lot less mysterious.
