# Day 020 — T5 E2E Testing

## Topic
Mobile emulation test suites

## Tweet 1/5 — Hook
Resizing your browser to 375px wide isn't mobile testing. You're testing responsive CSS, not mobile behavior. Touch events, device pixel ratio, the `matchMedia('(hover: none)')` flag, orientation APIs — none of those change on a resized desktop window.

## Tweet 2/5
CDP's `Emulation.setDeviceMetricsOverride` puts the browser into a true mobile state. `mobile: true` changes how the engine reports itself to JS — `navigator.userAgentData.mobile`, touch event support, and viewport scaling all flip to their mobile values.

## Code snippet (tweet 3/5)
```python
await cdp_send("Emulation.setDeviceMetricsOverride", {
    "width": 390,
    "height": 844,
    "deviceScaleFactor": 3,  # iPhone 14 Pro
    "mobile": True,
    "screenOrientation": {"type": "portraitPrimary", "angle": 0}
})
# Also enable touch events
await cdp_send("Emulation.setTouchEmulationEnabled", {"enabled": True})
```

## Tweet 4/5
Now you catch real mobile bugs: touch-start handlers that don't fire, mobile-only redirects, iOS Safari layout quirks (negative margin collapsing differently), and the infamous 100vh viewport bug that only hits real mobile rendering.

## Tweet 5/5 — Anchor
Testing with `setDeviceMetricsOverride` means testing the actual rendering engine in mobile mode. Everything else is "looks okay at 375px" which is not the same thing.
