# Day 027 — T5 E2E Testing

## Topic
Trace file debugging with CDP

## Tweet 1/4 — Hook
Your test suite is slow and you don't know which part. Is it the network? The selector wait? The CDP roundtrip itself? Stop guessing — CDP has a built-in profiler and most automation devs have never used it.

## Tweet 2/4
The `Tracing` domain records a Chrome trace: V8 execution, layout, paint, network, compositor — everything. cdpilot triggers `Tracing.start`, runs your test steps, then `Tracing.end`. Load the resulting JSON into DevTools Performance tab. The flame chart shows you exactly where your time went.

## Tweet 3/4
Common findings when you actually look at the trace: a 2MB unblocked image that delays DOMContentLoaded by 800ms; a 3rd-party analytics script that locks the main thread for 200ms before your click target is interactive; a CSS animation that causes continuous layout reflow.

## Tweet 4/4 — Anchor
"I think it's the network" vs the actual trace showing 600ms of main-thread JS from a tracking pixel. Data-driven debugging every time. The trace doesn't lie.
