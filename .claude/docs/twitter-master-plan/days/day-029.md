# Day 029 — T7 History

## Topic
WebDriver protocol standardization — what it got wrong

## Tweet 1/4 — Hook
The W3C WebDriver spec is a 2010 solution to a 2010 web. It brought order to chaos, but it also brought synchronous HTTP roundtrips for every browser action. Why did we spend a decade waiting for an HTTP response to confirm a single click?

## Tweet 2/4
WebDriver was designed for cross-browser compliance testing — the goal was "does this button work in Firefox AND IE AND Safari." High-level, slow, and deliberately abstracted. When SPAs arrived, "ready state" became meaningless and WebDriver never caught up.

## Tweet 3/4
CDP filled the gap. Events, streaming, binary protocol, sub-millisecond event delivery. Chrome-only, yes — but the raw power gap was undeniable. WebDriver BiDi is the W3C's answer: CDP-speed with cross-browser compatibility. Still early but the direction is right.

## Tweet 4/4 — Anchor
cdpilot lives in the CDP world because that's where the power is today. Standards are coming, but the raw protocol still wins on feature depth and latency. History repeats: the standard always lags behind what the engine actually can do.
