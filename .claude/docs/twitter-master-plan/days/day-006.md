# Day 006 — T6 Performance & Scale

## Topic
Browser process lifecycle

## Tweet 1/3 — Hook
Chromium spawns one browser process and one renderer process per tab. Crash one tab, browser lives. Crash the browser process, everything dies. Do you actually know where your memory is going?

## Tweet 2/3
For scale, you want many contexts — not many processes. Process-per-tab is a memory disaster at 50+ tabs. `Target.createBrowserContext` creates isolated worlds (cookies, storage, cache) within the same browser process. One browser, N parallel contexts.

## Tweet 3/3 — Anchor
cdpilot's context pool reuses the browser process and swaps contexts per task. At scale on a mid-range VPS, it's the only viable model. Process-per-tab will bankrupt your cloud bill.
