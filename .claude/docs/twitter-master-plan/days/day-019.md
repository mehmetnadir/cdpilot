# Day 019 — T4 Stealth Engineering

## Topic
ServiceWorker registration stealth

## Tweet 1/4 — Hook
ServiceWorkers persist across sessions, survive cache clears, and can fingerprint registration timing. Most "stealth" guides ignore the SW thread entirely. Why does every automation checklist stop at navigator properties?

## Tweet 2/4
Anti-bot signals from ServiceWorkers: registration happens too fast relative to page load, SW scope doesn't match typical user browsing patterns, or the same SW fingerprint appears across different IPs. The SW cache is sticky — it survives `Network.clearBrowserCache`.

## Tweet 3/4
cdpilot's context pool creates isolated storage partitions per context via `Target.createBrowserContext`. Each context gets its own SW registration scope, cache storage, and IndexedDB namespace. No SW state leaks between sessions. Clean slate every time.

## Tweet 4/4 — Anchor
It's not just about the UA string or canvas pixels anymore. The background threads you didn't know were running are leaving traces. Stealth engineering in 2026 means thinking about every persistent browser API.
